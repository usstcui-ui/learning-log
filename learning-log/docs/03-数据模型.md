# 学习记录网站 · 数据模型与统计规则

> 配套文档：`01-需求文档.md`、`02-页面结构.md`
> 本文档定义 TypeScript 类型、IndexedDB 表结构、索引、仓储接口、派生统计规则与导出格式。开发时以此为准。

---

## 1. 基础约定

| 约定 | 说明 |
| --- | --- |
| ID | `crypto.randomUUID()` 生成的 UUID v4 字符串 |
| 日期 | `YYYY-MM-DD` 字符串，表示**本地日历日**，不带时区 |
| 时间戳 | ISO 8601 字符串，带时区偏移，如 `2026-10-31T14:05:22.123+08:00` |
| 删除 | 软删除：`deletedAt: ISODateTime \| null`，所有查询默认 `deletedAt == null` |
| 版本 | `db.version(n)` 递增，配 `upgrade()` 迁移 |
| 单位 | 时长统一用**分钟（整数）**存储，展示时再换算 |

> 为什么日期用字符串：`new Date('2026-10-31')` 在部分环境会按 UTC 解析，导致"晚上 11 点打卡被算到前一天"。用纯字符串比较与排序，不存在时区漂移。

## 2. 类型定义

```ts
// src/data/types.ts
export type ID = string;
export type DateStr = string;      // 'YYYY-MM-DD'
export type ISODateTime = string;  // ISO 8601 with offset

export interface Tag {
  id: ID;
  name: string;              // 1–12 字，唯一（忽略大小写）
  color: string;             // 预设色值，如 '#4F46E5'
  createdAt: ISODateTime;
  deletedAt: ISODateTime | null;
}

export interface CheckIn {
  id: ID;
  date: DateStr;             // 学习发生的日期
  tagIds: ID[];              // 至少 1 个
  durationMin: number;       // 1–1440
  content: string;           // 学习内容（必填，≤2000）
  gain: string;              // 收获（可空）
  question: string;          // 疑问（可空）
  nextPlan: string;          // 下一步（可空）
  attachmentIds: ID[];       // 图片附件，最多 6
  noteId: ID | null;         // 反向快捷引用（真实绑定在 Note.checkInId）
  templateId: ID | null;     // 使用了哪个模板（统计用，可空）
  createdAt: ISODateTime;
  updatedAt: ISODateTime;
  deletedAt: ISODateTime | null;
}

export interface Note {
  id: ID;
  title: string;             // 可空，保存时若空则取正文首行
  body: string;              // Markdown + KaTeX
  tagIds: ID[];
  checkInId: ID | null;      // 绑定的打卡
  createdAt: ISODateTime;
  updatedAt: ISODateTime;
  deletedAt: ISODateTime | null;
}

export interface Attachment {
  id: ID;
  blob: Blob;                // 压缩后的图片
  mime: string;              // 'image/jpeg' | 'image/png' | 'image/webp'
  width: number;
  height: number;
  size: number;              // 字节
  createdAt: ISODateTime;
}

export interface Template {
  id: ID;
  name: string;
  builtin: boolean;          // 内置模板不可删除，可复制
  content: string;           // 「章节 / 内容」段落
  gain: string;
  question: string;
  nextPlan: string;
}

// 草稿：只存原始表单文本，不参与统计
export interface Draft {
  id: ID;                    // `checkin:new` | `checkin:<id>` | `note:new` | `note:<id>`
  kind: 'checkin' | 'note';
  payload: string;           // JSON.stringify(表单对象)
  updatedAt: ISODateTime;
}

// 计时器会话（同时只存在一条 id='current'）
export interface TimeSession {
  id: 'current';
  mode: 'stopwatch' | 'countdown';
  targetMs: number;          // 正计时为 0
  accumulatedMs: number;     // 已累计
  runningSince: ISODateTime | null; // 运行中为开始时刻，暂停为 null
  tagIds: ID[];
  memo: string;
  startedAt: ISODateTime;
}

export interface Settings {
  id: 'app';
  theme: 'light' | 'dark' | 'system';
  weekStartsOn: 1 | 0;       // 1 = 周一
  dailyGoalMin: number;      // 默认 60
  lastExportAt: ISODateTime | null;
  updatedAt: ISODateTime;
}
```

## 3. IndexedDB 表结构（Dexie）

```ts
// src/data/db.ts
import Dexie, { type Table } from 'dexie';

export class AppDB extends Dexie {
  tags!: Table<Tag, ID>;
  checkIns!: Table<CheckIn, ID>;
  notes!: Table<Note, ID>;
  attachments!: Table<Attachment, ID>;
  templates!: Table<Template, ID>;
  drafts!: Table<Draft, ID>;
  sessions!: Table<TimeSession, ID>;
  settings!: Table<Settings, ID>;

  constructor() {
    super('learning-log');
    this.version(1).stores({
      tags:        'id, name, deletedAt',
      checkIns:    'id, date, [date+createdAt], createdAt, deletedAt, *tagIds',
      notes:       'id, updatedAt, deletedAt, checkInId, *tagIds',
      attachments: 'id, createdAt',
      templates:   'id, name',
      drafts:      'id, kind',
      sessions:    'id',
      settings:    'id',
    });
  }
}
```

### 3.1 索引说明

| 表 | 索引 | 用途 |
| --- | --- | --- |
| `checkIns` | `date` | 按日范围查询（热力图、区间统计） |
| `checkIns` | `[date+createdAt]` | 同一天内按创建时间排序 |
| `checkIns` | `*tagIds` | 多值索引，按标签筛选与聚合 |
| `checkIns` | `deletedAt` | 过滤已删除（部分场景） |
| `notes` | `updatedAt` | 列表按更新时间倒序 |
| `notes` | `checkInId` | 由打卡反查笔记 |
| `tags` | `name` | 重名校验 |

> `deletedAt` 为 `null` 时 Dexie 也能索引，但范围查询要用 `where('deletedAt').equals(null)` 或直接内存过滤。数据量小（< 1 万），**筛选优先用内存过滤 + 索引范围取数**，代码更简单。

### 3.2 常用查询示例

```ts
// 某区间打卡（用于统计与热力图）
db.checkIns
  .where('date').between('2026-10-01', '2026-10-31', true, true)
  .filter(c => c.deletedAt == null)
  .toArray();

// 某标签下的打卡
db.checkIns.where('tagIds').equals(tagId).filter(c => c.deletedAt == null).toArray();

// 打卡绑定的笔记
db.notes.where('checkInId').equals(checkInId).filter(n => n.deletedAt == null).toArray();
```

## 4. 统计规则（全部由打卡派生）

**不存储任何累加值。** 所有指标在读取时从 `checkIns` 计算，并用 `useMemo` 缓存。

### 4.1 基础聚合

```ts
interface CheckInSummary {
  totalMin: number;      // 总时长
  count: number;         // 条数
  days: number;          // 有记录的自然日数
  byDay: Record<DateStr, number>;  // 每日时长
  byTag: Record<ID, number>;       // 每标签时长（均分后）
}
```

### 4.2 多标签时长均分（关键规则）

一条打卡有 `k` 个标签时，每个标签分得 `durationMin / k`。

```
打卡 A：45 分钟，标签 [算法, 读书]
→ 算法 +22.5，读书 +22.5
```

**为什么均分而不是"每个标签都记满"**：否则标签时长合计 = 45 × k，占比总和超过 100%，与总时长对不上。均分保证：

```
Σ byTag 值 = totalMin   （允许浮点误差）
Σ 占比 = 100%
```

展示时用一位小数，并做最大余数法修正，保证各行百分比相加恰好为 100%。Top 8 之外的合并为"其他"，其值 = 总和 − Top8 之和。

### 4.3 连续打卡天数

```ts
function calcStreak(activeDates: Set<DateStr>, today: DateStr):
  { current: number; includingToday: boolean; lastDate: DateStr | null }
```

规则：

1. 取最近一次有打卡的日期 `last`
2. 若 `last < 昨天`：`current = 0`（断签），`includingToday = false`
3. 否则从 `last` 往前逐日回溯，连续则 `current++`，遇到无记录日停止
4. `includingToday = (last === today)`

**边界**：昨天有、今天还没打卡时，`current` 仍显示昨天的连续数，UI 加"今天待打卡"字样，**不归零**。这样避免"每天早上看到 0"的挫败感。

### 4.4 热力图档位

```ts
function levelByMinutes(min: number): 0 | 1 | 2 | 3 | 4
// 0: 0；1: 1–29；2: 30–59；3: 60–119；4: ≥120
```

不随每日目标变化，保持全年可比。每日目标只用于"今日达标"。

### 4.5 折线图时间序列

必须**补零**，而不是只画有记录的日期：

```ts
function buildSeries(byDay, from: DateStr, to: DateStr): { date: DateStr; min: number }[]
```

区间按 `weekStartsOn` 对齐（周一起）。跨月、跨年时用 `date-fns` 的 `eachDayOfInterval` 生成。

### 4.6 出勤率

`days / 区间天数`，区间天数含首尾（10 月 1 日至 10 月 31 日 = 31 天）。

### 4.7 首页累计值

| 指标 | 计算 |
| --- | --- |
| 累计时长 | 全部未删除打卡求和 |
| 本月时长 | `date` 在本月范围内求和 |
| 本月打卡天数 | 本月去重日期数 |
| 最长连续 | 遍历全部日期序列求最长连续段（可在导入后计算一次并缓存到内存） |

### 4.8 性能约定

- 单次统计只查一次区间数据，在内存中聚合，不逐日发查询
- 一年数据 ≈ 365 条打卡，内存聚合耗时 < 5ms，无需索引优化
- 笔记搜索在 < 1000 篇时直接 `includes` 扫描即可

## 5. 仓储层接口

页面**不得**直接 `import db`。所有数据操作经由 `src/data/repository`。

```ts
// src/data/repository/checkInRepo.ts
export const checkInRepo = {
  list(opts?: {
    from?: DateStr; to?: DateStr;
    tagIds?: ID[];
    keyword?: string;
    limit?: number; offset?: number;
  }): Promise<CheckIn[]>,

  get(id: ID): Promise<CheckIn | undefined>,
  create(input: NewCheckInInput): Promise<CheckIn>,
  update(id: ID, patch: Partial<CheckIn>): Promise<void>,
  softDelete(id: ID): Promise<void>,
  restore(id: ID): Promise<void>,
  summarize(from: DateStr, to: DateStr): Promise<CheckInSummary>,
};

// 同理：tagRepo / noteRepo / attachmentRepo / templateRepo / draftRepo / sessionRepo / settingsRepo
```

约定：

1. 所有写操作内部统一补 `updatedAt`
2. `create` 负责生成 id、时间戳与默认值
3. 查询默认过滤 `deletedAt != null`
4. 换后端时，只替换这些文件里的实现（Dexie → fetch），页面零改动

## 6. 关键业务流程

### 6.1 提交打卡

```
表单数据 → 校验（日期/标签/时长/内容）
        → 压缩图片（若有）→ 写 attachments 表
        → 写 checkIns 表（生成 id/时间戳）
        → 删除对应 drafts 记录
        → Toast 成功 → 跳转 /checkins 或 /（视来源）
```

**事务**：图片写入与打卡写入放在同一个 `db.transaction('rw', [attachments, checkIns], ...)` 内，任一失败全部回滚，避免产生孤儿图片。

### 6.2 删除打卡

```
软删除打卡 → 保留附件（避免误删不可恢复）
          → 若有关联笔记，笔记的 checkInId 置 null（不删笔记）
```

### 6.3 删除标签

```
标记 tag.deletedAt
→ 打卡的 tagIds 保留该 id（不物理移除）
→ 展示时查不到标签 → 显示为「已删除标签」灰色 chip
→ 统计时该部分时长归入「未分类」
```

**为什么不从 tagIds 里移除**：移除会丢失历史归因。保留 id 后，即使标签被删除，历史数据仍可追溯，且未来恢复标签能自动复原。

### 6.4 计时器状态机

```
idle → running → paused → running ...
                ↘ finished（生成打卡页）

running:   elapsedMs = accumulatedMs + (now - runningSince)
paused:    elapsedMs = accumulatedMs
```

持久化规则：

| 事件 | 写入 |
| --- | --- |
| 开始 | `{ accumulatedMs: 0, runningSince: now }` |
| 暂停 | `{ accumulatedMs: elapsed, runningSince: null }` |
| 恢复 | `{ runningSince: now }`（accumulated 不变） |
| 结束 | 删除会话，跳转打卡页 |
| 页面加载 | 读取会话，`runningSince != null` 则继续计算 |

### 6.5 草稿恢复

```
进入新建页 → draftRepo.get('checkin:new')
  → 存在且 payload 解析成功 → 填充表单，标题栏提示「已恢复上次草稿」
  → 解析失败（版本变更）→ 忽略并删除坏草稿，不阻断编辑
```

**编辑既有记录时不走草稿**，避免"草稿覆盖真实数据"。离开时用 `beforeunload` + 路由拦截提示未保存。

## 7. 数据导入导出

### 7.1 全量 JSON 格式

```json
{
  "app": "learning-log",
  "version": 1,
  "exportedAt": "2026-10-31T22:10:00.000+08:00",
  "data": {
    "tags": [...],
    "checkIns": [...],
    "notes": [...],
    "templates": [...],
    "settings": {...},
    "attachments": [
      { "id": "...", "mime": "image/jpeg", "width": 1600, "height": 1200, "size": 240000, "data": "<base64>" }
    ]
  }
}
```

- 图片以 base64 内联，保证单文件可完整备份
- 导入时校验 `app` 与 `version`，版本高于当前则拒绝并提示
- **合并模式**：按 `id` 去重，冲突时以文件中数据为准（并更新 `updatedAt`）
- **覆盖模式**：清空所有表后写入，需输入确认

### 7.2 CSV

见 `02-页面结构.md` 8.3。要点：

- UTF-8 + BOM
- 标签名而非标签 id（便于人读）
- 字段转义：`"` → `""`，含 `,` `"` `\n` 时整体加引号

### 7.3 Markdown 导出

```
notes-zip/
├─ 动态规划设计套路.md
├─ 英语从句笔记.md
└─ attachments/
   └─ <attachmentId>.jpg
```

文件头写入元信息：

```md
---
title: 动态规划设计套路
date: 2026-10-31
tags: 算法, 读书
checkInDate: 2026-10-31
---
```

## 8. 校验规则汇总

| 字段 | 规则 | 失败提示 |
| --- | --- | --- |
| `date` | 必填；≤ 今天；≥ 今天 − 30 天 | 不能记录未来 / 最多回补 30 天 |
| `tagIds` | 长度 ≥ 1，id 均存在且未删除 | 请至少选择一个标签 |
| `durationMin` | 整数，1–1440 | 时长需在 1–1440 分钟之间 |
| `content` | 非空，≤ 2000 字 | 请填写学习内容 |
| `gain`/`question`/`nextPlan` | ≤ 2000 字 | 最多 2000 字 |
| `attachmentIds` | ≤ 6 | 最多上传 6 张图片 |
| 图片 | mime ∈ {jpeg, png, webp}，压缩后 ≤ 500KB | 仅支持 JPG / PNG / WebP |
| `Tag.name` | 去空格后 1–12 字，不重名 | 标签名已存在 / 名称需 1–12 个字 |
| `Note.title` | ≤ 100 字 | 标题最多 100 字 |

## 9. 迁移策略

每次改表结构：

1. `this.version(n + 1).stores({...}).upgrade(tx => {...})`
2. 迁移函数只做数据补齐，不删字段（保留 `legacy` 兼容读取）
3. 上线前用真实导出数据跑一遍迁移测试
4. 迁移失败时捕获异常，提示用户"数据升级失败，请先导出备份"，并阻止继续写入（只读模式）
