# 学习记录网站 · 需求文档

> 版本：v1.1
> 定位：**个人自用**的学习打卡与笔记工具，单用户，不做注册登录与社区。
> 核心原则：**打卡要快、笔记要留得住、统计要看得见。**
> 本版本按用户确认的六个页面组织：首页、打卡页、打卡记录、统计、笔记、设置。目标是**与复习**不在本版本范围内（见第 9 节）。

---

## 1. 产品定位

### 1.1 一句话描述

每天花 1 分钟打卡"学了多久、学了什么、有什么收获和疑问"，配一个能写公式的笔记区，一年后回看热力图和时长曲线，知道自己到底投入在哪。

### 1.2 目标用户

只有你自己。因此：

- 无需账号、权限、多租户
- 无需审核、社交、排行榜
- 数据量级在几千条打卡、几百篇笔记以内，不需要分库分表
- 单机可用即可，同步作为可选增强

### 1.3 核心问题与解法

| 问题 | 解法 |
| --- | --- |
| 记录工具太重，打开就放弃 | 打卡默认只填「标签 / 时长 / 学什么」，其余字段可留空 |
| 学了很久说不清投入在哪 | 热力图 + 时长折线 + 标签时长占比 |
| 笔记散落各处，找不回来 | 独立笔记库，Markdown + 公式，全文搜索，可绑定打卡 |
| 只记不想，学了就忘 | 打卡固定四段结构（学会 / 疑问 / 下一步），强迫输出 |
| 数据怕丢、怕被锁死 | CSV + JSON 导出，Markdown 打包导出 |

### 1.4 明确的非目标

- 不做多人协作、好友、排行榜、公开主页
- 不做课程商城、题库、视频
- 不做移动原生 App（以 PWA 替代）
- 本版本不做目标管理、间隔复习（预留位置，见第 9 节）

## 2. 信息架构

### 2.1 两类内容实体

| 实体 | 作用 | 关系 |
| --- | --- | --- |
| **打卡 CheckIn** | 记录"某天学了多久、学了什么"，是统计的唯一数据源 | 一条打卡可关联 0~N 篇笔记 |
| **笔记 Note** | 长期沉淀的知识内容，可写长文、公式、代码 | 一篇笔记可绑定 0~1 条打卡 |

> 关键区分：**打卡是事件，笔记是资产。** 打卡有时长、有日期、进统计；笔记不参与时长统计，只做检索与沉淀。这样统计口径只有一个，不会出现"笔记和打卡各算一次"的重复计数。

### 2.2 页面清单

| 页面 | 路由 | 职责 |
| --- | --- | --- |
| 首页（仪表盘） | `/` | 今日概览、快捷入口、热力日历、累计数据、最近打卡 |
| 打卡页 | `/checkin/new`、`/checkin/:id/edit` | 新建 / 编辑打卡，草稿、模板 |
| 打卡记录 | `/checkins` | 时间倒序列表、搜索、标签筛选、编辑删除 |
| 统计 | `/stats` | 时长折线、标签占比、月热力图 |
| 笔记列表 | `/notes` | 笔记列表与搜索 |
| 笔记详情 / 编辑 | `/notes/new`、`/notes/:id` | Markdown + 公式编辑与预览，绑定打卡 |
| 设置 | `/settings` | 标签管理、主题、导出备份 |

全局常驻：**计时器**（右下角悬浮，可展开为面板）。

## 4. 技术选型

### 4.1 推荐方案：纯前端 + 本地数据库

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 启动快、配置少 |
| 框架 | React + TypeScript | 类型安全，改数据模型时不易漏改 |
| 样式 | Tailwind CSS | 改版快，便于做深色模式 |
| 路由 | React Router | 标准方案 |
| 状态 | Zustand | 轻量，适合放设置与筛选条件 |
| 存储 | IndexedDB（Dexie） | 可存 Blob（图片）、支持索引查询 |
| 图表 | Recharts（折线 / 环形）+ 自绘 SVG 热力图 | 热力格用 SVG 更可控 |
| Markdown | react-markdown + remark-gfm | GFM 语法 |
| 公式 | remark-math + rehype-katex | 数学公式渲染 |
| 代码高亮 | rehype-highlight 或 shiki | 轻量优先 |
| 日期 | date-fns | 按需引入 |
| 图片压缩 | browser-image-compression | 上传前压到长边 1600 |
| 打包导出 | JSZip | Markdown 与图片打包 |
| 测试 | Vitest + Testing Library | 与 Vite 同源 |

**选择纯前端的原因**：单用户、单机、数据量小，后端只会增加部署成本与故障点。静态托管即可，零运维。

**代价**：数据只在当前浏览器。缓解措施：

1. IndexedDB + `navigator.storage.persist()` 申请持久存储
2. 14 天未导出即提醒
3. CSV / JSON / Markdown 三条导出口子
4. 所有数据访问走仓储层，日后可换后端

### 4.2 第二阶段（需要多端同步时）

| 方案 | 适用场景 |
| --- | --- |
| Supabase（Postgres + Auth） | 想在手机和电脑间自动同步 |
| 本地 SQLite + Hono | 有常开的机器或 NAS，数据存成单文件 |
| WebDAV 同步单个 JSON | 只想同步一份快照，冲突较难处理 |

约束：**页面组件不得直接调用 Dexie**，只能调用 `src/data/repository`。换存储时只改这一层。

## 5. 关键设计决策

### 5.1 打卡是统计的唯一事实来源

时长、热力图、连续天数、标签占比全部由打卡派生，不存储任何累加计数器。避免"计数器与明细对不上"。

### 5.2 日期存字符串 `YYYY-MM-DD`

IndexedDB 存 Date 会受时区影响。"学习发生在哪一天"应按本地日历理解，用字符串最稳，排序与范围查询都直接可用。时间戳另用 ISO 字符串存，用于排序与显示时刻。

### 5.3 图片单独建表，存 Blob

不要把图片转 base64 塞进打卡 JSON：会让单条记录膨胀数十倍，列表页读取缓慢，导出也臃肿。用 `attachments` 表存 Blob，打卡只存附件 id。

### 5.4 软删除

打卡、笔记、标签删除只标记 `deletedAt`，查询时过滤。误删可恢复，未来可直接做回收站。

### 5.5 草稿与正式数据分离

草稿存 `drafts` 表，不进入打卡表，因此不会污染统计。提交时才写入 `checkIns`。

### 5.6 计时器用时间戳而非累加

`TimeSession = { startedAt, accumulatedMs, runningSince }`，已用时长 = `accumulatedMs + (runningSince ? now - runningSince : 0)`。这样刷新、切页、休眠后仍然准确，"每秒 setInterval 加 1"在后台标签页会被节流，不能依赖。

### 5.7 移动端优先

打卡多发生在"刚学完、拿着手机"的场景。布局以小屏为起点，桌面放大为左侧导航 + 双栏。

## 7. 验收标准

### M1

1. 首次打开无数据时，页面不报错，显示引导与「新建第一个标签」
2. 新建打卡只填标签、时长、内容三项即可提交，全程不超过 6 次交互
3. 刷新页面后数据仍在
4. 打卡可编辑、可删除，删除需确认
5. 输入内容后强制刷新页面，草稿可恢复
6. 按标签筛选与关键词搜索，结果正确且无闪烁

### M2

7. 热力图颜色档位与当日时长正相关，无记录日为空白格；跨月边界正确
8. 连续天数：昨天有打卡、今天未打卡时显示"连续 N 天（今天待打卡）"，不归零
9. 折线图在无记录日期补 0，曲线连续不断裂
10. 标签占比总和等于所选区间总时长（允许 0.1% 舍入误差）

## 8. 风险与对策

| 风险 | 影响 | 对策 |

| 浏览器清缓存丢数据 | 高 | 申请持久存储 + 备份提醒 + 三种导出 |
